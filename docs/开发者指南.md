# 开发者指南

## 1. 项目结构

```text
apps/
  web-host/
packages/
  core/
  host-web/
  mode-canvas/
  mode-map/
  exporter/
  shared-ui/
docs/
```

分层原则：

1. `core` 负责协议、状态、命令、插件，不依赖宿主和模式。
2. `mode-*` 依赖 `core`，不依赖 `host-*`。
3. `host-*` 依赖 `core`，不依赖 `mode-*`。
4. `apps/web-host` 负责最终装配。

## 2. 本地开发命令

```bash
pnpm install
pnpm dev
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

## 3. 核心开发流程

### 3.1 新增业务操作（推荐）

1. 在 `mode-canvas/runtime.ts` 或 `mode-map/runtime.ts` 增加运行时方法。
2. 注册对应命令 ID。
3. 在 `App.tsx` 工具栏绑定 `commandBus.execute(...)`。
4. 补单元测试与 E2E。

### 3.2 新增模式包（示例）

1. 创建 `packages/mode-xxx`。
2. 提供 `runtime` 入口（纯逻辑）。
3. 提供 `pixi` 入口（渲染）。
4. 在 `apps/web-host` 添加别名与懒加载接入。

## 4. 文档与测试同步规范

1. 变更对外 API 后，必须更新 `docs/API手册.md`。
2. 协议字段变更后，必须同步更新导入导出用例。
3. 每次收口至少执行：`lint/typecheck/test/build/test:e2e`。

## 5. 性能与稳定性建议

1. 渲染能力优先走懒加载，避免首屏引入重型图形依赖。
2. 视口组件避免使用不稳定依赖触发重复初始化。
3. E2E 中保留关键闭环：导出、合法导入、非法导入、相机状态变化。

## 6. 小游戏集锦主界面实现建议

### 6.1 UI 布局建议

使用 CSS Grid 五区布局：

1. `header`：工具条。
2. `left`：游戏目录。
3. `main`：2D 视口。
4. `right`：游戏详情。
5. `footer`：状态栏。

### 6.2 状态映射建议

1. `core.store.document.nodes`：中间视口中的游戏入口节点。
2. `core.store.selection`：当前选中游戏。
3. `map viewport camera`：视口浏览位置和缩放状态。
4. `exporter`：布局方案序列化与恢复。

### 6.3 命令设计建议

1. `hub.game.create`：新增游戏入口节点。
2. `hub.game.move`：拖动节点。
3. `hub.game.select`：设置选中游戏。
4. `map.camera.pan/zoom`：控制视口。
5. `hub.layout.save/load`：持久化当前布局。
